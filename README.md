## 今回の修正

- 元金請求額を「担当元金 − 他案件からの確定充当 − 一時預かり金からの確定充当」で計算し、0円を下限にします。実入金は請求額から控除しません。
- 元金管理と帳票で同じ計算を使用し、内訳・確定日・充当履歴・超過額を表示します。
- プレビュー後の充当変更、0円請求、同じ案件・下請けへの二重発行を防止します。
- 発行済みPDFと金額は入金や通常の備考編集で変更しません。金額訂正は明示操作で行い、旧PDF・旧スナップショットを履歴に残します。
- 起動先・版・コード・データ保存先の照合と、バックアップ後にコードだけを更新する仕様を維持します。

## 既存データを保持する更新

**更新専用です。会社・下請け・仕入先の登録データ、DB、実パスワード、社印、実取引履歴、発行済みPDF、バックアップを含みません。**

1. 利用中アプリの「設定→バックアップ」で全体バックアップを保存します。外部のPDFコピー先も保管してください。
2. PCを再起動し、LOGIBOXはまだ開きません。ブラウザを閉じるだけでは旧サーバーは終了しません。
3. 新しいZIPを利用中フォルダとは別の場所へ展開し、`logibox/update.bat`を開きます。Python 3.10以降が必要です。
4. 現在のデータがある利用中の`logibox`フォルダを選択します。`data/app.db`が必要です。
5. 更新ツールは停止状態・配布ファイルを確認し、フォルダ全体を隣接する`LOGIBOX-before-0.6.8-*/full-installation.zip`へ保存・照合してからコードを更新します。
6. 更新後は利用中フォルダの`起動.vbs`を開き、ver.0.68の表示と既存データ・PDFを確認します。

`APP_DATA`で保存先を変更している場合は自動更新を中止します。管理者が保存先とバックアップを確認してください。空の更新パッケージから起動しても新しいDBは作成しません。

公開用に、固定の帳票宛先・住所と、テスト・文書の顧客固有の名前・案件番号を除去・匿名化しました。請求書テンプレートに会社情報や社印はありません。新規ハーク請求書の固定宛名は「請求先」となります。既存の発行済みPDF・保存済みスナップショットは変更しません。テスト用の架空データ・ダミーパスワードと、対応帳票形式の識別名・画面の業務ラベルはソースに含みます。

## 検証

Pythonの各テストファイルを独立プロセスで実行し、unittest 214件中211件成功、3件スキップ、失敗0件。別途HTTP APIスモークテストとJavaScript構文検査に成功しました。

生成した配布ZIPで旧0.6.7の架空データ入りフォルダを更新し、全dataファイルのSHA256・全テーブルのSQL内容・更新前バックアップの一致を確認しました。初回初期化後も業務テーブル内容を保持します。

Windows実機でのVBS・PowerShell・ショートカット操作は未実行です。スキップは未提供のPDFサンプル2件とWindows管理者トークン専用1件です。本番データは使用していません。

ZIPは`SHA256SUMS.txt`、各配布ファイルは`logibox/SOURCE_MANIFEST.json`で照合できます。ソースは`logibox/`です。`python logibox/build_release.py`でデータを含まない配布ZIPを再生成できます。
